# epub2audiobook-rs Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** A Rust CLI that converts an EPUB into a chapter-tagged M4B audiobook using local neural TTS, playable offline on an iPhone (or anything else) with no server and nothing running.

**Architecture:** Single Cargo workspace, one binary. `abook` does EPUB parse -> text normalization -> TTS synthesis -> M4B assembly, then exits. The `.m4b` is a finished artifact you copy to your phone. TTS sits behind a `TtsEngine` trait so Kokoro (default), Piper (fast draft), and a remote Chatterbox worker (GPU, voice cloning) are interchangeable.

**Playback target:** iPhone, offline. M4B is Apple's native audiobook format (MP4/AAC + chapter markers). Because the user is on Arch (no Finder/iTunes sync), the recommended path is iCloud Drive or Dropbox -> Files app -> BookPlayer (free, open source). Audiobookshelf is the scale-up option; its iOS app downloads for offline playback. **Nothing needs to be running to listen.**

**Tech Stack:** Rust 2024 edition, sherpa-rs 0.6.8 (ONNX Runtime wrapper), Kokoro-82M ONNX, rbook 0.7.10 (EPUB), lofty 0.24 (M4B tags + chapters), clap 4, rayon, indicatif.

## Proposed Approach

```
┌─ crates/abook-core ──────────────────────────────┐
│  epub::Book      rbook parse, TOC, cover, meta   │
│  normalize::     numbers, abbrevs, roman, notes  │
│  chunk::         split to TTS-sized segments     │
│  tts::TtsEngine  trait  { synth(&str) -> Pcm }   │
│     ├─ KokoroEngine   (sherpa-rs)   default      │
│     ├─ PiperEngine    (sherpa-rs)   --fast       │
│     └─ RemoteEngine   (HTTP)        Chatterbox   │
│  assemble::      Pcm -> AAC -> M4B + chapters    │
└──────────────────────────────────────────────────┘
        │                              │
   bin/abook (laptop)          bin/abook-play (Pi)
```

Phased so each phase ends in something usable:
- **Phase 1** EPUB -> clean text (replaces haydonryan's tool entirely)
- **Phase 2** + Kokoro TTS -> WAV per chapter
- **Phase 3** + M4B assembly with chapter markers
- **Phase 4** + Piper/remote backends, resume, parallelism
- **Phase 5** Pi player
- **Phase 6** packaging

## Phase 1: EPUB -> Clean Text

### Task 1.1: EPUB parsing with rbook

**Files:** Create `crates/abook-core/src/epub.rs`, test `crates/abook-core/tests/epub_test.rs`

TDD: fixture EPUB in `fixtures/`, test that title, author, chapter count, and cover bytes extract correctly.

```rust
pub struct Book {
    pub title: String,
    pub author: Option<String>,
    pub cover: Option<Vec<u8>>,
    pub chapters: Vec<Chapter>,
}
pub struct Chapter { pub index: usize, pub title: String, pub text: String }
```

### Task 1.2: HTML -> plain text

Strip tags, preserve paragraph breaks, drop `<sup>` footnote markers, collapse whitespace. Test against a chapter with nested markup, entities, and footnotes.

### Task 1.3: TOC-based chapter titles with fallback

haydonryan's known weak spot — do it properly. Match spine items against the TOC/nav document; fall back to first `<h1>`/`<h2>`, then to `Chapter N`.

### Task 1.4: Front/back matter detection

Heuristic flag for index, TOC, appendix, copyright, "about the author" — so the user can `--skip-frontmatter` instead of manually deleting files (haydonryan's step 2).

### Task 1.5: Text normalization module

**Files:** Create `crates/abook-core/src/normalize.rs`

**This is the highest-value module in the project — CONFIRMED EMPIRICALLY in Phase 0, not assumed.** Both defects heard in the spike listen-test (`1904` read as "nineteen hundred four", and an unwanted pause after `Dr.`) collapse into this one module. See BENCHMARKS.md Finding 2: normalization reclaimed 0.53-1.00s of spurious pause per sentence in A/B tests.

Two distinct jobs:

**(a) Pronunciation** — feed Kokoro words, not symbols:
- Years: `1904` -> `nineteen oh four` (spike confirmed Kokoro says "nineteen hundred four" otherwise)
- Ordinals, cardinals, decimals, currency, percentages
- Roman numerals in chapter headings
- Acronym spacing

**(b) Sentence-boundary protection** — the pause bug. sherpa's splitter treats any `.` as end-of-sentence, so abbreviations produce a prosody drop mid-sentence. Expand them so no period survives:
- Titles: `Dr.` -> `Doctor`, `Mr.` -> `Mister`, `Mrs.` -> `Missus`, `St.` -> `Saint` or `Street` (context-dependent!)
- `p.m.`/`a.m.` -> `PM`/`AM`, `etc.` `e.g.` `i.e.` `vs.`
- Em-dashes / ellipses -> pause punctuation that IS wanted

`St.` is genuinely ambiguous (`St. John` vs `Elm St.`) — resolve by position and capitalization of the following token.

One unit test per category. The A/B harness in `spike/src/main.rs` is the model for validating changes by ear.

### Task 1.6: User replacement rules

Support `custom-replacements.conf` (`pattern==replacement`, `#` comments) for compat with haydonryan's format, applied after built-in normalization.

### Task 1.7: `abook extract` subcommand

```bash
abook extract book.epub -o ./out/
```
Writes `NNN-chapter-title.txt`, `metadata.json`, `cover.jpg`.

**At this point the tool already replaces haydonryan/epub2audiobook.** Commit and tag `v0.1.0`.

## Phase 2: TTS Synthesis

### Task 2.1: Define the `TtsEngine` trait

**Files:** Create `crates/abook-core/src/tts/mod.rs`

```rust
pub struct Pcm { pub samples: Vec<f32>, pub sample_rate: u32 }

pub trait TtsEngine: Send + Sync {
    fn synth(&self, text: &str) -> Result<Pcm>;
    fn sample_rate(&self) -> u32;
    fn name(&self) -> &str;
}
```

Keep it this small. Everything else is an implementation detail.

### Task 2.2: Text chunking

Neural TTS degrades on long input. Split on sentence boundaries into ~200-400 char chunks, never mid-sentence. Test that chunks rejoin to the original text.

### Task 2.3: `KokoroEngine`

Wrap sherpa-rs. Config: model dir, voice id, speed. Test: synth a short string, assert non-empty samples at expected rate.

### Task 2.4: Parallel chapter synthesis

`rayon` across chapters, `indicatif` progress bar. Thread count via `--threads`, default `num_cpus - 1` to keep the laptop usable.

### Task 2.5: `abook synth` subcommand

```bash
abook synth ./out/ --engine kokoro --voice af_heart
```
Writes `wav/NNN.wav`. Resumable: skip chapters whose WAV already exists.

## Phase 3: M4B Assembly

### Task 3.1: PCM -> AAC encode

Shell out to ffmpeg initially (it's installed, it's reliable). Note as a future pure-Rust swap; YAGNI for now.

### Task 3.2: Concatenate + chapter markers

Single `.m4b`, one chapter marker per source chapter, correct cumulative timestamps. **This is the main feature haydonryan's tool lacks** (he emits a pile of MP3s).

### Task 3.3: Metadata + cover via lofty

Title, author, narrator (engine+voice), embedded cover art.

### Task 3.4: `abook build` — the one-command path

```bash
abook build book.epub -o audiobook.m4b
```
extract -> normalize -> synth -> assemble, resumable, one progress bar.

**Tag `v0.2.0`.** This is the "better than everything else available" milestone.

### Task 3.5: `--sample` for fast feedback

**High value, cheap to add — do this before any full-length render.**

```bash
abook build book.epub --sample -o sample.m4b        # first chapter only
abook build book.epub --sample 3 -o sample.m4b      # chapter 3
```

Renders a single chapter (~15 min of audio) so the voice and text normalization can be judged on the phone before committing to a multi-hour run. This is the tightest feedback loop in the project.

### Task 3.6: `--format mp3-split` compat mode

Per-chapter tagged MP3s for audiobookshelf users who want the old layout.

## Phase 5: Getting It Onto Your iPhone

**Phase 5 was originally a Raspberry Pi Zero 2 W playback device. CUT.** The user listens on an iPhone, never on the laptop. A phone is already a better audiobook player than anything we'd build, so the Pi player solved a problem that doesn't exist. Cutting it removes the DAC HAT purchase, the cross-compile toolchain, GPIO controls, PiSugar integration, and the systemd unit.

The Pi may return later as an **Audiobookshelf server** — but the Zero 2 W's 512MB is marginal for it (Node-based), so that would want a Pi 4/5. Separate decision, only if the library grows.

This phase is now documentation, not code.

### Task 5.1: Verify M4B plays correctly on iPhone

Render a real book, get it onto the phone, confirm: chapter list appears, resume works, playback speed works, lock-screen and CarPlay controls work.

**Recommended path (no Mac, no iTunes, works from Arch):**
1. Upload the `.m4b` to iCloud Drive via icloud.com in Firefox (or Dropbox).
2. On iPhone: Files app -> locate the file -> Share -> BookPlayer.
3. Plays fully offline. Nothing running anywhere.

Apps that read the Files app: **BookPlayer** (free, open source, recommended), Bound, Chapters, Prologue.

Apple Books also reads M4B natively but normally wants Finder/iTunes sync, which doesn't exist on Linux — so it's the worst option for this user despite being the "official" one.

### Task 5.2: Document transfer options in README

Cover: iCloud web upload, Dropbox, Syncthing to a watched folder, and Audiobookshelf (self-hosted; its iOS app downloads books for **offline** playback and syncs position across devices).

Make the key point explicit up front: **`abook` runs once to produce a file, then exits. No server, no daemon, no laptop involvement at playback time.**
